# 设计规范：Material Design 3 × Mochi Compose 对齐

> 适用：Web 单文件、Windows（Avalonia）、Android（WebView 壳）、HarmonyOS（ArkTS）四端全部 UI。
> 基准：**Web 端 `deploy/monolith-web/index.html` 的 CSS 变量**为唯一事实源，其余三端逐项对齐。
> 参照：Material Design 3（含 Expressive）+ `mochi-compose` 的设计规范与 token 实现。
> 维护契约：本文件与 `scripts/verify_design_tokens.py` 同源；改 token 必须同提交更新本文件。

## 〇、来源与取舍

| 方面 | 来源 | 本项目的落法 |
|---|---|---|
| 配色 | MD3 tonal + 本项目品牌语义 | **保留品牌色**（章节蓝/词绿/债红/主蓝 #0D72D9），只对齐**结构**：语义分层、成对 on-* 关系、深浅色都成立 |
| 形状 | MD3 八档刻度 + G2 连续曲率 | 四端统一八档；卡片/面板用 `extraLarge`（28）；现有旧值一律映射到最近档 |
| 间距/行高 | mochi 的 iOS 26 单元格实测值 | 列表行最小 52、左右 16、图标块 28、符号图标 24、行内上下留白 10 |
| 动效 | MD3 Expressive + mochi 八档弹簧 | 八档命名与参数完全照 mochi；不手写数字 |
| 交互 | mochi 的七级优先级 | 见第二节；冲突时按优先级裁决 |
| 材质 | mochi「实体」路线 | 不做玻璃折射/模糊大面积；Web 现有轻玻璃（`--glass-*`）**保留**，但不得新增折射类效果 |

**不做的事**：不把品牌色换成 mochi 默认色；不引入 AGSL/液态玻璃（非 Compose 栈无法实现，且偏离本项目「实体」定位）。

## 一、形状系统（唯一刻度）

| 档位 | 值 | 用途 |
|---|---:|---|
| `extraSmall` | 4 | 徽标、极小标签 |
| `small` | 8 | 小按钮、输入框内小元件、**原 10px 归此档** |
| `medium` | 12 | 常规按钮、次级容器 |
| `large` | 16 | **卡片默认**（原 18px 归此档）、列表图标块 |
| `largeIncreased` | 20 | 大卡片、强调容器 |
| `extraLarge` | 28 | 面板、抽屉、图谱容器 |
| `extraLargeIncreased` | 32 | 外壳、**原 36px 归此档** |
| `extraExtraLarge` | 48 | 全屏面板顶部 |
| `full` | capsule | 胶囊按钮、标签、导航项 |

规则：

1. **只允许上表九个值**。新增组件必须从表中取，不得出现 10、18、36 这类档间值。
   > 2026-11-22 已确认：四端统一到本表为**终态**，不再回退到旧值。
2. **同心圆角**：圆角容器内贴边元素，内圆角 = 外圆角 − 内边距。例：28 面板内缩 16 放卡片 → 12。
3. **卡片默认 `large`(16)**；面板/抽屉用 `extraLarge`(28)；外壳用 `extraLargeIncreased`(32)。
4. **胶囊一律 `full`**，不用大数字模拟（Harmony 的 `999` 属此语义，保留）。
5. 四端变量名固定：

| 端 | 文件 | 变量 |
|---|---|---|
| Web | `index.html` `:root` | `--r-xs` `--r-s` `--r-m` `--r-l` `--r-xl` `--r-2xl` `--r-3xl` `--r-4xl` `--r-pill` |
| Windows | `AppTheme.axaml` | `RadiusXs` … `RadiusPill` |
| HarmonyOS | `Theme.ets` | `R_XS` … `R_PILL` |

## 二、交互优先级（冲突时按此裁决）

照 mochi 的七级，越靠前越优先：

1. **跟手与可用性**：拖动必须逐帧跟随；可点区域不小于 44×44；系统关闭动画时立即完成。
2. **不出错、不裁切**：内容不被裁掉、不遮挡相邻内容。
3. **几何规范**：同心圆角、四周等距。
4. **光学平衡**：图标按墨迹居中（非包围盒）；仅在几何规范内微调。
5. **内容不瞬切**：状态变化有过渡；拖动中的读数直接显示。
6. **细节还原**：能还原的还原，不能的在文档写明。
7. **性能与兼容**：效果按能力降级，功能不降级。

## 三、色彩系统

1. **只用语义变量**，组件里不写死色值（品牌内容除外：图谱三色、教材封面、拍照画面）。
2. 语义分层照 MD3：`primary / onPrimary / primaryContainer / surface / onSurface / surfaceVariant / outline / outlineVariant / error / onError`。本项目现有变量按此归类：

| MD3 语义 | 本项目变量 | 值 |
|---|---|---|
| `primary` | `--primary` | #0D72D9 |
| `surface` | `--surface` / `--card` | #FBFBFC |
| `background` | `--canvas` | #F3F4F5 |
| `surfaceVariant` | `--soft` / `--well` | #E8EAEC |
| `onSurface` | `--ink` | #303236 |
| `onSurfaceVariant` | `--muted` | #62676C |
| `outline` | `--rule` | #C7CACF |
| `error` | `--danger` | #B64A58 |

3. **成对约束**：每个容器色必须有对应 `on-*` 前景色，深色模式两者同时切换。
4. 禁用态统一 `opacity: .4`（对应 mochi `DisabledAlpha`）。
5. 图谱三色（章节蓝 `--ch-*`、词绿 `--t-*`、债红 `--d-*`）是**业务语义色**，不参与 MD3 语义替换，但必须满足 AA 对比度。
6. 不做渐变底色装饰；现有渐变仅限进度条（`--primary`→`--primary-soft`）。

## 四、排版

1. 字号只用五档：`12 / 13 / 15 / 17 / 20`（caption/body-sm/body/title/headline），不得新增。
2. 行高按居中分配（中文不偏下），与同行图标中心对齐。
3. 长标题先缩字号再省略，不硬裁。
4. 数字用等宽数字（`font-variant-numeric: tabular-nums`）避免跳动。

## 五、间距系统（4 的倍数）

| token | 值 | 用途 |
|---|---:|---|
| `sp-1` | 4 | 图标与文字最近距 |
| `sp-2` | 8 | 紧凑间距、胶囊留白 |
| `sp-3` | 12 | 控件内边距 |
| `sp-4` | 16 | **卡片内边距、列表左右边距（标准）** |
| `sp-5` | 20 | 面板内边距 |
| `sp-6` | 24 | 大区块间隔 |
| `sp-8` | 32 | 段落级间隔 |

列表行（照 mochi/iOS 26）：最小行高 **52**（正文 22 + 上下各 15），图标块 **28**、到文字 **15**；符号图标 **24**、到文字 **16**；双行标题与副标题间距 **4**。

## 六、动效系统（八档，参数照 mochi）

| 档位 | 参数（时长 / 阻尼比） | 用途 | CSS |
|---|---|---|---|
| `page` | 0.42s / 1.00 | 页面切换、标签页、进度值 | `--mo-page` |
| `present` | 0.42s / 0.86 | 面板升起、Toast | `--mo-present` |
| `pop` | 0.36s / 0.78 | 对话框、气泡 | `--mo-pop` |
| `control` | 0.34s / 0.86 | 拖动吸附、取消弹回 | `--mo-control` |
| `settle` | 0.28s / 1.00 | 收起、高度变化、展开箭头 | `--mo-settle` |
| `bounce` | 0.34s / 0.55 | 角标、选中框 | `--mo-bounce` |
| `press` | 0.22s / 0.62（按下）、0.38s / 0.62（松开） | 按压 | `--mo-press-down` / `--mo-press-up` |
| `fade` | 150ms 进 / 120ms 出 | 透明度 | `--mo-fade-in` / `--mo-fade-out` |

规则：

1. 组件里**不写数字**，从八档取；确实没有合适档位时先在本文档加一档并写明用途。
2. 透明度独立于位移/尺寸，用 `fade` 档，不用弹簧进度当透明度。
3. 可打断：中途改目标从当前值继续，不跳回起点。
4. 同一次变化多个组件参与时，读同一档位，不各挑参数。
5. `prefers-reduced-motion: reduce` 时全部立即完成（Web）；对应端跟随系统动画开关。

## 七、组件与状态（最低要求）

1. **可点区域 ≥ 44×44**，视觉可以更小，点击区不外扩到相邻元素。
2. **按压有反馈**：按下即变（亮度/缩放 0.98），松手回弹；滚动容器内按压延迟 90ms 启动，滚动接手则取消。
3. **焦点可见**：键盘导航有 2px 描边（现有 `:focus-visible` 保留），不依赖颜色单独传达状态。
4. **空状态**：有图标 + 一句事实描述 + 一个可执行动作，不用「暂无数据」了事。
5. **加载**：超过 300ms 才显示骨架/加载态，避免闪烁。
6. **错误**：说明发生了什么、能做什么，不暴露堆栈与内部码。

## 八、文案（照 mochi 第十一章）

1. 每句话让用户多知道一件事：这页能做什么、这个值是什么、出什么问题、下一步怎么办。
2. 不写「沉浸式 / 极致 / 丝滑 / 赋能」这类说不出事实的词。
3. 标题与数量、状态与解释不用「·」硬拼一行；数量放行尾，次要信息放副标题或完整句子。
4. 不用 emoji 当图标，图标用统一图标集。

## 九、四端一致性

1. **Web 是基准**，其余三端逐项对齐；任一端新增 token 必须四端同提交。
2. 对齐校验由 `scripts/verify_design_tokens.py` 执行：
   - 圆角值必须属于九档集合；
   - 四端圆角/间距关键值一致；
   - 动效八档变量齐备；
   - 组件内不得出现档间字面量圆角。
3. 端侧能力差异（如 WebView 无原生弹簧）**允许实现不同，语义必须一致**：用 CSS 的 `cubic-bezier(.22,1,.36,1)` 近似弹簧，参数表仍以第八节为准。
