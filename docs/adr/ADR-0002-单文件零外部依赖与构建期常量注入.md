# ADR-0002 · 单文件产物零外部依赖与构建期单一事实源

- 状态：**已接受（Accepted）**
- 日期：2026-10-25
- 关联：深度优化方案 P2-9（单文件内联 ONNX）与 P2-10（T21 阶段三：性能、常量注入、覆盖率、风格门禁）

## 背景

1. 自包含单文件 `astralpath-monolith.html` 此前仍保留 `https://cdn.jsdelivr.net/npm/onnxruntime-web` 一处外链：离线或 CDN 不可达时，ONNX 意图分类只能降级到同构 JS 前向，「零外部依赖」的承诺不完整。
2. 前端公式常量 `K` 与 `src/AstralPath.Core/Formula/FormulaConstants.cs` 由人工同步，历史上出现过两侧漂移，只能靠 `verify_constants.py` 事后发现。
3. 覆盖率作业长期 `continue-on-error`，覆盖率下降不会阻断合并；C# 与前端也没有统一的格式门禁。

## 决策

1. **ONNX 运行时内联**：`scripts/build-single.py` 把 `deploy/monolith-web/ort-runtime/ort.min.js` 与 `ort-wasm-simd-threaded.wasm`（后者 base64）写入单文件产物；页面通过 `window.__AP_ORT_INLINE__` 在运行时解出 blob URL 喂给 ORT。源目录版仍保留 CDN `<script>`（带 `onerror` 降级哨兵），两条路径失败时回退同构 JS 前向。
2. **公式常量构建期注入**：`scripts/gen_formula_constants.py` 从 C# 常量生成 index.html 的 `/* AP:BEGIN formula-constants */` 生成区，`--check` 作为 CI 与 verify_all 门禁；JS 独有的 `SpacingOffsets` 保留字面量并注明。
3. **覆盖率转硬门禁**：`scripts/verify_coverage.py` 解析 Cobertura，行覆盖 ≥50%、分支覆盖 ≥40%，CI `coverage gate` 作业移除 `continue-on-error`。
4. **风格门禁**：C# 用 `dotnet format whitespace --verify-no-changes`（只卡空白/换行，不把命名分析器当格式门禁）；前端用 eslint（只开会导致真 bug 的规则，集成脚本关闭 `no-undef`）。

## 后果

- 正面：单文件真正离线可用；常量、覆盖率与格式漂移都会在 CI 变红；产物可用 Playwright 直接断言「0 个外部 `src`/`href`」。
- 负面：单文件从 18.2 MB 增至约 31.5 MB（wasm base64 约 14.2 MB）；构建机必须能取得 LFS 中的 wasm；ORT 初始化失败时仍需接受同构 JS 的精度差异。
- 回退：`scripts/build-single.py --no-onnx-inline` 可保留 CDN 引用；覆盖率阈值与格式范围都在单点脚本内，可独立调整。
